# Agent Wolf — executability audit of the 24 unbuilt tickets

**Date:** 2026-08-21 · **Method:** six independent opus auditors at xhigh effort, one group of four
tickets each, followed by a deduplicating synthesis pass. Companion to
`design/2026-08-20-agent-wolf.md`; that plan remains the source of truth for *what to build*, this
document is the record of *where the plan cannot yet be executed unattended*.

**Why this exists.** Wave 1 (O1, O7, W1) ran autonomously. O1 and O7 passed first time. W1 failed
verification three times, every round on one under-specified criterion. This audit asks whether the
remaining 24 tickets carry the same defect shapes, before they are dispatched.

# Agent Wolf plan — remediation list (from 6 audits, 105 raw findings)

**Headline answer first: No.** 35 of the 105 findings are `blocking`; after dedup they are **26 distinct blocking defects** spread over **21 of the 24 unbuilt tickets** (only O2, W2 and W4 have no blocking defect confined to themselves, and all three are hit by cross-cutting ones). ## Pile A — plan edits only (no decision needed)

### Tier 1 — systemic, each spans a whole wave

**A1. Validation commands that cannot execute the criteria they gate — 8 tickets.**
Merges: O2, O3 (`-run 'TestDataset'` vs the repo's `TestLivePG_*` naming), O8 (`-run 'TestGC'` does not match `TestResolveGCConfig` — unanchored substring), O9 (`go/systemtest` is behind `//go:build integration`; the command matches no packages and **exits 1**), O10 (both "commands" are human judgements over a file the same ticket authors), O11 (`-run 'TestMemor'` excludes all four `TestRetraction*` and all six `TestListMemories_*` — i.e. every test that covers the function being edited), W9 (`yarn test src/hypothesis/provision` never runs the route criteria), W12 (`yarn test scripts/bootstrap-project` matches zero files — `api/vitest.config.ts` includes only `src/**`).
Fix: one pass over every Validation block. Add `-tags integration` where required; pin the test-name prefixes in each ticket's Scope so the filter and the convention agree; add `-v` + "must show `--- PASS`, zero `--- SKIP`" wherever a live-Postgres or Docker skip can vacuously exit 0. This is R35 recurring eight times — add it as a house rule in § Executor orientation.

**A2. The dataset byte plane: one blob prefix, two seams, no import cycle — O3, O6a, O6b, O8, O9.**
Merges 6 findings. `agentdb` cannot import `extension` (`extension.go:12` imports `agentdb`), so O3's pinned signatures `ReapDatasetVersions(ctx, keepPerName)` and `ListOrphanBlobPaths(ctx, knownPrefix)` are *structurally unimplementable* — the first cannot delete a blob, the second cannot enumerate one and can only return the set of *known* paths, the exact inverse of its name (and O8's sweep would then delete every live dataset blob). Compounding it, the blob namespace and prefix are named nowhere: O6a says only "unique per call", agentd runs **one global BlobStore** shared with `_artifacts/bytes/` and snapshots, so an empty or wrong prefix enumerates artifact and snapshot blobs for deletion. `BlobStore.Put`, cited by O6a, does not exist (the interface is `Write/Read/Exists/Delete/List`).
Fix: state the constant once in § Interfaces (`_datasets/bytes/<uuid4>`, global namespace, declared as `agentdb.DatasetBlobPrefix`, cited by O3/O6a/O8); change both O3 signatures to take locally-declared `DatasetBlobDeleter` / `DatasetBlobLister` interfaces; correct `Put`→`Write`; and give O8's orphan sweep acceptance criteria (it currently has **zero** — an executor shipping no sweep passes every criterion) including a re-assert of the prefix immediately before every `Delete` and a skip for blobs younger than 1h.

**A3. The dataset read plane: three packages, no ticket owns the crossings — O4, O5, O6b, O9.**
Merges 5 findings. (a) `apiAuthMiddleware` 401s any request with no `X-API-Key`/`Bearer` *before* the handler, so O5's `?token=` download route — the exact call O6b's tool description and O9 require — is unreachable; `auth.go` is owned by nobody. (b) `httpapi` has no way to read a blob (`Config.Artifacts` is host-wired precisely because of this) and O5's Files list has no `main.go`. (c) `verifyDatasetToken` is placed in `package main` and its only consumer is `package httpapi` — Go cannot import it; the natural home for the scope helpers, `extension/devclaims`, is in no ticket's Files list. (d) The scope value is stated twice, incompatibly: `dataset:<project>/<name>` (§ ticket) vs `dataset:<id>` (§ File Structure) — the second pins a version and breaks the plan's own "a URL minted before a tick still resolves after it".
Fix: add `go/cmd/agentd/{auth.go,auth_test.go,main.go}` and `go/extension/devclaims/*` to O4/O5's Files; put the `?token=` leg in the middleware (path-scoped) with a test that drives the real middleware, not the bare handler; declare `DatasetBlobReader` in `httpapi` (keeps the no-`extension`-import rule at `memories.go:129`); correct L806 to the name form.

**A4. Dataset metadata JSON — the response body is literally elided — O5, O6b, W2, W10, W11, X1.**
`{"datasets":[…metadata…]}` with no field list, and the single-name route's envelope (`{…}` vs `{"dataset":{…}}`) is unstated. O5 ships first and picks; five later tickets are written against a choice recorded nowhere. Failure mode is silent: W10's version gate compares `undefined !== undefined` and re-downloads every CSV 288×/day while its own mocked test passes.
Fix: pin the exact struct in § Interfaces (`id,name,version,labels,size_bytes,row_count,sha256,content_type,created_by_worker,created_by_session,created_at` in **unix ms**; `blob_path` and `project` never serialised), pin both envelopes, and require O6b's `dataset_list` field names to be byte-identical.

**A5. Wolf file-ownership gaps — 7 files that many tickets must edit and no ticket owns.**
Merges 6 findings. `api/src/bob/client.ts` (W2's scope omits `include_retracted` for W5, session LIST for W5/W9/W10, `attention-requests` for W10, `project-settings` for W12 — none of which owns the file); `api/src/config.ts` + `.env.example` (W6, W7, W8, W9, W10, W11, W12 all add variables; assigned to W1 alone; R41 flagged half of this and it is still open); `api/src/app.ts` + `api/src/index.ts` (every route ticket must mount a router, W10 must start an interval — neither file appears anywhere, and W10 ‖ W11 are parallel-eligible on both); `api/src/hypothesis/store.ts` (W8's board read of `kind=evaluation` memories, owner row says W5+W10 only); `api/src/routes/hypotheses.ts` (W10 must add attention-requests); `web/src/App.tsx` (W14 must register its route into W13's file).
Fix: make W2's route list exhaustive and closed; add the files to the Files lists; add five rows to § "Parallelism and file ownership" marked strictly serial.

**A6. Time units — the plan's own rule ("encode the unit in every type") is broken in six places.**
Merges 5 findings, one of them blocking. `expires_at` (W11→W13) — Orange returns unix **seconds**; W13 computes a T-120s refresh and will subtract 120 from ms or 120_000 from seconds, giving a token that never refreshes or refreshes instantly, invisible in either ticket's own test. `points[].t` (W11→W14, W4's `Point`) — RFC3339 string vs epoch ms vs epoch s, renders 1970 with no error. `WOLF_TEARDOWN_DRAIN_TIMEOUT`/`WOLF_POLL_INTERVAL` — "60s"/"5m" never say what the *variable* holds. W2's branded-type criterion is unbuildable as written (field names create no TS incompatibility).
Fix: rename to `expires_at_sec`, `tMs`, `fetched_at_ms`, `*_SECONDS`; declare `UnixMs`/`UnixSec` brands in W2 with a `@ts-expect-error` fixture as the proof.

**A7. Cross-ticket shared values in Wolf, each with 4+ consumers.**
- **Canonical dataset CSV** (W10, W11, W12, X1, and O6a's `row_count`): the byte format of a dataset is stated nowhere — only `series_fetch`'s is. A `t,value` vs `timestamp,value` divergence makes the poller read zero observations from a legitimately-written dataset, with no error anywhere. Pin `timestamp,value`, RFC3339 UTC, ascending, LF, one metric per dataset, in § "The dataset atom"; add a W12 criterion that `researcher-preamble.md` states it verbatim.
- **`row_count` arithmetic** (O6a → O6b shrink guard, O9, W10): "lines minus one header" is undefined for no-trailing-newline, header-only and empty files — one reading stores **−1** in a `NOT NULL DEFAULT 0` column that the 50% shrink guard then divides by. Pin `max(0, N−1)` with the six boundary tests.
- **`tamper` field shape** (W5, W8, W13, W14, X1): specified nowhere; must distinguish forged row from hostile retraction because X1's spec asserts on both attacks and a bare string cannot tell them apart. Pin `{reason, written_by_worker, written_by_session, memory_id}`.
- **`EvaluationResult` top level + `Point`** (W4 → W8, W10, W11, W14): only the per-condition shape exists. W14 requires per-metric direction, realised change and staleness that no W4 criterion produces — W14 is not buildable without reopening W4. Pin `{evaluated_at_ms, support_score, conditions[], metrics[]}` and `Point = {tMs, v}`.
- **MCP server name + header** (W7, W12, X1): Orange rejects partial interpolation (`sessions.go:79-90`), so `"Bearer ${WOLF_MCP_TOKEN}"` **cannot be stored** — only a bare whole-value header. W7 will build `Authorization: Bearer`, W12 can only send a raw value, both tickets' tests pass, X1 fails with a 401 from inside a container. Pin server name `wolf` (tool names `mcp__wolf__*`, which X1's mock script and the researcher prompt must both use) and header `X-Wolf-Mcp-Token` carrying the bare token.
- **`<id>` vs `hyp-<id>`** (W3, W5, W8, X1): W5 says ids *are* `hyp-<8 hex>`; W8 creates sessions named `hyp-<id>` = `hyp-hyp-1a2b3c4d`, under which the trust rule "`name` matches an existing `hyp-<id>` session" never matches. Fix in § Vocabulary and correct the three sites.
- **The trust rule says "five kinds"; § Memory kinds lists six** (W5, W10): `evaluation` was added by R29 and the numeral was never updated. If W5's executor enumerates five, every memory W10 writes is untrusted, the board silently shows no `support_score`, and no test in either ticket fails.
